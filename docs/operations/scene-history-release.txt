Scene-answer delivery correction — 26 November 2026

Problem and behaviour
PR41 deployed successfully with all 60 transitive source hashes matching its
tested tree. Its first live tests confirmed two-episode context selection.
One scene answer passed the unchanged factual/spoiler review, was saved, and used
one question, but the post-save history gate rejected it with HTTP 409. That gate
still excluded every scene answer citing a previous episode. The frontend uses
the same gate, so it would also hide the saved answer after a backend-only fix.

This correction admits properly scoped earlier-episode citations for scene
answers only when current-episode evidence is present too. The existing title,
episode, timestamp, source-version and earlier-order checks remain in place.
An earlier-only scene answer or an explicit current-episode-only request still
cannot pass with historical citations. Rewinds still exclude later answers from
model memory; the UI keeps its already-shipped same-episode history behaviour.

The corrected gate returns the existing verified answer on a same-request retry
or history read. It does not regenerate the answer or charge another question.
Work/check revisions advance to watch-work-2026-11-26-scene-history-v2 and
watch-checks-2026-11-26-scene-history-v2.
