Recap grounding correction — 26 November 2026

Problem and behaviour
PR38's live range/season recap checks returned safe fallbacks after identity or
speaker rejection. The old logs cannot identify the exact rejected wording.
Private reconstruction exposed a concrete false positive: "Googling" was treated
as a new identity despite an original receipt naming Google. The independent
review had already accepted the paragraph. Source-backed grammatical forms now
match only that explicitly named service; this is not general fuzzy name matching.
Regression tests also reproduce chronology prefixes such as "Meanwhile Mira"
being mistaken for the person's complete name. The actual name still needs its
own original receipt and positive independent attribution review.

If a recap passes its overall boundary/relevance review but a subset of paragraphs
fails only identity/speaker checks, the second writer replaces only those sections.
Previously verified paragraphs retain their exact text. The writer receives
verified text, failed paragraph indexes, fixed issue codes and permitted source
IDs. Rejected prose and reviewer explanations are never passed into the retry.
The ENTIRE combined answer then receives a fresh independent review and all
original local checks. Earlier verdicts are not supplied to the final reviewer.
Invalid, missing, duplicate or extra replacement indexes fail closed. Global
spoiler/relevance failures, other failure types and non-recap requests retain the
existing full-rewrite behaviour. Maximum attempts/model-call count is unchanged.
