CineGeek mobile password recovery — 23 November 2026

Observed
The owner reports the public /reset-password route displays CineGeek's own 404
in normal iPhone Safari but correctly displays Reset your password in Private
Safari. The same route works on the laptop and in a fresh browser check.
Unauthenticated desktop and iPhone HTTP requests receive identical HTML, HTTP
200 and no-cache headers. This isolates the problem to existing browser state;
the offline app shell is the likely stale source. We have not inspected the
phone's stored service worker version directly.

The email's redirect destination is already the correct public reset route.
No owner reset token was followed, redeemed or saved in the repository.

Correction
Exclude /auth and /reset-password from Workbox's offline navigation fallback.
Do not register the automatic reload handler on authentication pages or when a
recovery intent was captured. An automatic update after Auth consumes the URL
would otherwise discard the in-memory verified recovery event.
Normal app navigation retains its existing offline caching and update behaviour.
Native builds continue to omit service workers. Recovery ownership verification,
password validation and expired/used-link handling are unchanged.

Local verification
- 22 tests pass: the actual Workbox NavigationRoute matching, registration during
  recovery, ordinary web/native navigation, recovery owner checks and sign-in.
- TypeScript and git diff --check pass.
- Production web and native web builds pass.
- Generated dist/sw.js contains the auth/reset navigation denylist.

Release and acceptance
Merge the reviewed fix and publish the web build only after deployment approval.
No backend migration, authentication-setting change or new TestFlight build is
required for the browser fix. Do not change production purchase flags or AI caps.
Existing old workers need to receive the new worker before their navigation
behaviour changes. A one-time refresh/site-cache cleanup may still be needed for
an already-stale browser; never promise a local change repaired that device.
The immediate workaround is a fresh reset email requested and completed in the
same Private Safari session. The user enters and submits the password directly.
Require successful iPhone app sign-in with the new password before marking the
owner's recovery complete. Do not reuse a link already redeemed on the laptop.
