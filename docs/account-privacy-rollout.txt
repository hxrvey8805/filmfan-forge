password from a verified email link, and review or withdraw permission separately

Live acceptance checks
- Unsigned /privacy and /support load; the exact support contact is clickable.
- An ordinary signed-in session or an expired recovery link cannot set a password.
- A disposable test account receives a real recovery email; its newest link sets
  a new password and returns to sign-in. A used link cannot reset again. The user
  enters any new password or verification code directly; none belongs in logs.
- With permission unset/declined/withdrawn, companion and list-helper requests
  fail before source or provider work and before quota/reservation changes.
  Verify independently using two disposable accounts; do not opt in the owner.
- Save each permission, reload and check it persists for only its account.
- Wrong password and an old bearer cannot delete. Delete ONLY an explicitly
  disposable account seeded for this check. Confirm associated active records,
  local items and Focus tokens disappear; control account and aggregate spend stay.
- Deletion explains Apple renewal and remains possible with active subscription.
  Never delete the owner's everyday or existing purchase-test accounts.
- Purchases remain disabled, Sandbox behavior and caps unchanged. No paid AI call
  is needed to check the new gate; the answer engine and spoiler logic are unchanged.
